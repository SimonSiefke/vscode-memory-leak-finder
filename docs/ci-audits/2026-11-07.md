## Diagnosed causes and candidate changes

### Markdown Git cleanup

The Windows video for run 42392601382 shows both the fixture repository and its enclosing harness checkout. The first ordinary failure is in Markdown teardown; subsequent repository-count assertions inherit the extra model. Teardown previously enabled Git and explicitly reopened the fixture during cleanup. It now disables Git, waits for repository models to disappear, and only then deletes `.git`. The next fixture replaces the settings normally.

The lifecycle regression fails against the old teardown for both initial Git states. All three candidate regression cases pass, including a delayed model-disposal barrier. On Linux, the baseline standalone test and three-run Markdown sequence passed; the Windows race was observed in the CI log/video, not claimed reproduced locally. All four candidate Markdown scenarios passed ten iterations on Linux. The Windows platform CI remains the acceptance gate for that timing.

### Cascades after failed scenarios

The forced `debug-javascript` sequence reproduces a setup failure in the intentionally skipped performance-profile scenario. The runner then reused the partially initialized app: the ordinary set-value test failed looking for the initial Run and Debug button, followed by two more debugger failures. Fresh app recovery retains the original profile failure while all nine other scenarios pass. Before recovery: one ordinary failure, three skipped failures, six passes. After recovery: one skipped failure and nine passes. No retry, new skip, or change to failure counters is involved.

The coordinator now replaces the app and workers before the next scenario after any setup, run, or teardown failure. Successful and normally skipped scenarios continue sharing the app. Video segments are finalized and archived before restart; encoder finalization waits for process closure so output can be moved safely on Windows. A deliberately failed setup followed by an independent editor scenario retained its failure exit code, passed the second scenario, and produced two decodable videos.

### Cancelled no-fixes request

`editor-no-autofixes-available.ts` failed alone on Linux at both one and 37 iterations. A DOM observer saw no overlay inserted. Keyboard invocation, enabling extensions, disabling nearby quick fixes, and waiting for language symbols/diagnostics did not repair it. Targeted controller instrumentation showed that an automatic code-action refresh replaced the manual request before a result was taken. All instrumentation and fixture probes were removed.

The no-fixes helper now reinvokes the operation while its expected message is absent, within a six-second message wait. It still asserts the exact message, propagates transport errors, and fails if no result appears. Operations that apply a fix execute once. The original scenario then passed all 37 iterations (97.6 seconds); five unit regressions cover cancellation, bounded failure, unexpected text, transport failure, and applying fixes once.
